# Лаба 7 — Архитектура, слои и DDD-lite (Go)

Система оплаты заказа, реализованная в стиле слоистой архитектуры (Domain / Application / Infrastructure) с упором на DDD-lite: доменная модель хранит бизнес-правила (инварианты), а сценарии использования (use-cases) оркестрируют процесс и обращаются к инфраструктурным зависимостям через интерфейсы.

## Слои и ответственность

### Domain (домен)
Содержит бизнес-модель и правила (инварианты):
- `Order` — сущность (aggregate root).
- `OrderLine` — часть агрегата.
- `Money` — value object (сумма + валюта).
- `OrderStatus` — статус заказа.

Инварианты (пример):
- Нельзя оплатить пустой заказ.
- Нельзя оплатить заказ повторно.
- После оплаты нельзя менять строки заказа.
- Итоговая сумма равна сумме строк заказа.

### Application (приложение)
Use-case `PayOrderUseCase`:
1) Загружает заказ через `OrderRepository`  
2) Вызывает доменную операцию оплаты  
3) Делает списание через `PaymentGateway`  
4) Сохраняет заказ  
5) Возвращает результат

### Infrastructure (инфраструктура)
Реализации интерфейсов:
- `InMemoryOrderRepository` — хранит заказы в памяти (без реальной БД).
- `FakePaymentGateway` — имитация платежей (внешний сервис не нужен).

### Tests
Тестируются:
- успешная оплата корректного заказа;
- ошибка при оплате пустого заказа;
- ошибка при повторной оплате;
- невозможность изменения заказа после оплаты;
- корректный расчёт итоговой суммы.
